# ElectionsIL — בחירות בישראל

דשבורד עברי, עצמאי וניטרלי למידע על הבחירות בישראל: חדשות ממקורות מגוונים, השוואת סיקור, עמודי מפלגות ואישים ולוח סקרים. האתר אינו מזוהה עם מפלגה, מועמד/ת או גוף תקשורת.

## הרצה מקומית

דרישות: Node.js 22.

```bash
npm ci
npm run dev
```

בדיקה ובנייה לפרסום:

```bash
npm run check
npm run build
```

## איך העדכון האוטומטי עובד — בדיוק

1. רשימת המקורות נמצאת ב־`public/sources.json`. לכל מקור שם, סוג, כתובת RSS ומתג `enabled`; זו הנקודה היחידה הנדרשת להוספה או השבתה של מקור.
2. GitHub Actions מפעיל את `.github/workflows/update-data.yml` בכל שלוש שעות, בדקה 17, וגם מאפשר הפעלה ידנית (`workflow_dispatch`).
3. הפעולה מתקינה את התלויות הנעולות באמצעות `npm ci` ומריצה `npm run update-data`.
4. `scripts/update-news.mjs` קורא עד 25 פריטים מכל פיד, שומר רק פריטים בעלי מילות הקשר לבחירות, מסיר HTML, מסווג לפי מילות מפתח ומגביל את **קטע תיאור ה־RSS של המקור** ל־280 תווים. קטע זה מסומן בממשק כקטע מקור ואינו מוצג כסיכום שיצר ElectionsIL. התוכן המלא לעולם אינו נשמר.
5. פריטים חדשים מתמזגים עם המאגר הקיים לפי כתובת המקור. אם פיד נכשל, השגיאה נרשמת והפריטים הישנים נשארים; אין מחיקה בגלל תקלה במקור. נשמרים עד 300 פריטים.
6. `npm run check` מאמת מבנה, טיפוסים, כתובות בטוחות, תאריכים, ייחודיות, הפניות למקורות, מקור קטעי RSS ומבנה סקרים. רק לאחר הצלחה, שינוי ב־`public/data/news.json` נרשם ב־commit אוטומטי ונדחף למאגר.
7. כל push מפעיל את `.github/workflows/deploy.yml`: אימות, בניית Vite, העלאת `dist` ופרסום ב־GitHub Pages.

> תיאורי RSS בשפה שאינה עברית נשמרים כפי שהמקור התיר ומסומנים כקטעי מקור. המאגר הראשוני ריק בכוונה: אין בו חדשות או סקרים מומצאים המיוחסים לארגונים אמיתיים.

## פרסום ב־GitHub Pages

ב־**Settings → Pages → Build and deployment**, בוחרים **GitHub Actions**. נתיב הבסיס של Vite נגזר אוטומטית מ־`GITHUB_REPOSITORY`. לאחר push לענף `main`, תהליך הפרסום בונה את `dist`, מעלה Pages artifact ומפרסם אותו באמצעות סביבת `github-pages`. בקשות משיכה מריצות בנפרד אימות נתונים ובניית production, ללא הרשאות כתיבה או פרסום.

## עריכה ועקרונות

- אין לעקוף חומות תשלום או להעתיק כתבות מלאות.
- כל פריט חייב לכלול מקור, כותרת מקורית, מחבר כשזמין, מועד וקישור ישיר.
- סיכומים צריכים להיות קצרים, עובדתיים, ולייחס טענות לדובריהן.
- ממוצע סקרים, אם יתווסף, יוצג בנפרד מסקר בודד ולעולם לא כתחזית.
- תיקונים מתקבלים ב־GitHub Issues ונשמרים בהיסטוריית Git.
